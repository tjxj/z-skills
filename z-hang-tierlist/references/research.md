# 查资料：方法、信源、搜索词

目标：榜上每一个分数，都能指到一条带链接、带日期的证据。

## 0. 先查最新

模型的知识有截止日期，世界一直在变。动手前先确认三件事：

1. 今天是哪天（看系统日期），`asof` 写今天
2. 这个主题最近 1-3 个月发生了什么：新品发布、改名、合并、倒闭、召回、榜单更新
3. 每个候选的「当前版本」：模型看最新版本号，手机看最新一代，品牌看最近一季数据

搜索词里带上年份和月份（「2026 年 11 月」「2026 Q3」「Nov 2026」），优先看最近的结果。记忆里的数字一律当作待核实，查到出处才能用。

## 1. 信源分级

| 级别 | 是什么 | 例子 | type | 怎么用 |
|---|---|---|---|---|
| A 一手 | 当事方自己公布的数据 | 官网、官方公告、财报、招股书、技术报告、官方定价页 | 官方 | 直接作为打分依据 |
| A 权威榜单 | 方法公开、持续更新的第三方榜单和统计 | LMArena、Artificial Analysis、OpenRouter 用量榜、App Store / Google Play 榜、SteamDB、豆瓣 / IMDb、猫眼 / 灯塔、乘联会 / 中汽协、Counterpoint / IDC / Canalys、TIOBE、Stack Overflow 调查 | 榜单 / 市场 | 直接作为打分依据，写清口径 |
| B 专业评测 | 有实测过程的评测 | 专业科技媒体实测、跑分、盲测、拆解 | 评测 | 作为依据，留意是不是商单 |
| B 权威媒体 | 有采编流程的报道 | 财新、晚点、36氪、界面、澎湃、路透、彭博、The Verge | 媒体 | 作为依据，引用其中的数字和事实 |
| C 口碑 | 用户评价的统计或有代表性的讨论 | 应用商店评分与评论数、大众点评评分、黑猫投诉量、知乎 / V2EX / Reddit / Hacker News 高赞讨论 | 口碑 | 做补充；单条帖子不能决定分数，尽量用统计值 |
| D 线索 | 没有出处或立场明显的内容 | 营销号、自媒体「排行榜」、品牌软文、AI 生成的总结、内容农场 | 不入表 | 只用来发现候选和关键词，顺藤摸瓜找 A / B 级原始出处 |

同一件事有一手来源时，引一手来源；二手报道转述的数字，尽量回溯到原始出处。

## 2. 三轮搜索

每轮都并行发多条搜索，中英文都搜。

### 第一轮：全景，定候选池

目的：找出该上榜的候选，别漏掉黑马，也别收录已经过气的。

- `{主题} 排行榜 2026` / `{主题} 排名 2026年11月`
- `{主题} 市场份额 2026 Q3` / `{主题} 销量榜 2026年10月`
- `{主题} 年度盘点 2026` / `{主题} 格局 2026`
- `best {topic} 2026` / `{topic} ranking November 2026` / `{topic} market share 2026`
- 主题对应的权威榜单直接去看（`rubrics.md` 每个主题下列了常用数据源）

产出：12-20 个候选 + 每个候选的「当前版本」，收录规则写进 `scope`。

### 第二轮：逐个查硬数据

每个候选按维度查，每个维度争取一条硬数字：

- `{候选} {指标}`：`{候选} 销量 2026`、`{候选} 评分`、`{候选} 价格`、`{候选} 月活`
- `{候选} 评测` / `{候选} 实测` / `{候选} vs {竞品}`
- `{候选} 财报` / `{候选} 发布会` / `{候选} 官方`
- 英文：`{candidate} benchmark` / `{candidate} review` / `{candidate} revenue`

### 第三轮：专门搜负面

榜单最容易翻车的地方是只看了好话。每个候选都搜一遍负面，进「拉完了」的必须找到实锤：

- `{候选} 翻车` / `{候选} 投诉` / `{候选} 召回` / `{候选} 争议` / `{候选} 差评`
- `{候选} 降智` / `{候选} 涨价` / `{候选} 停更` / `{候选} 裁员` / `{候选} 下架` / `{候选} 闭店`
- `黑猫投诉 {候选}` / `{候选} 监管 通报` / `{候选} 判决`
- 英文：`{candidate} controversy` / `{candidate} lawsuit` / `{candidate} recall` / `{candidate} problems`

搜到负面也要核实：是个例还是普遍，是已经修好的旧问题还是现在仍然存在。证据里写清时间。

## 3. 怎么记证据

边查边写进 `data.json`，别攒到最后：

```json
{"text": "2026 年 9 月门店 3210 家，一年净增 640 家（示意）", "source": "窄门餐眼", "url": "https://…/具体页面", "date": "2026-09", "type": "市场"}
{"text": "10 月因原料问题被市场监管局通报（示意）", "source": "澎湃新闻", "url": "https://…/具体页面", "date": "2026-10", "type": "媒体", "neg": true}
```

- `text`：一句话事实，带数字、带口径，不写形容词。「月活 1.2 亿（QuestMobile，2026 年 9 月）」好过「用户很多」
- `url`：落到具体那一页，别填首页
- `date`：数据的时间（发布日期或统计日期）
- 一条证据只说一件事；一个候选 2-5 条为宜
- 数字太多写不进 `text` 的，放 `summary`（依据表里会展示）

## 4. 来源打架怎么办

- 口径不同（不同榜单、不同统计周期）：都可以记，`text` 里写清口径
- 口径相同、数字不同：用更权威、更新的那个；拿不准就取对候选不利的那个（保守），在 `summary` 里写「A 说 x，B 说 y」
- 影响分档的关键数字只有一个来源：再找一个交叉验证，找不到就在 `summary` 里标「单一来源」

## 5. 时效

- 模型、手机、App、榜单、市场份额这类：只用最近 3 个月的数据，老数据只当背景
- 品牌口碑、游戏、影视、城市这类：近一年为主，经典作品可以用长期数据（如豆瓣总评分）
- 有新版本的以新版本为准；新版本刚发布、数据还不全的，在 `summary` 里写明

## 6. 分寸

- 评的是产品、作品、品牌、公司的公开表现，不评人品
- 公司负面只写可查证的事实：监管通报、法院判决、官方召回或致歉、投诉平台统计、权威媒体报道。传闻、爆料、未证实的指控不写
- 真人上榜（明星、主播、企业家）格外克制：只评作品和业绩，锐评不做人身攻击，不拿外貌和私生活开玩笑
- 不碰政治、宗教、民族、地域歧视；地名写到城市
- 识别商单：明显是推广的评测降一级使用

## 7. 工具

- 搜索：WebSearch，一次并行发 5-10 条；结果不够就换关键词、换语言
- 读网页：WebFetch（没有时用 web-fetch 子代理）读榜单页、官方页、长文
- 抓不到的站（部分社交平台、要登录的页面）：换一个转载了同样数据的权威来源
- 搜索词里不放用户的个人信息

## 8. 交差前自检

- [ ] 每个候选 ≥ 2 条证据、≥ 1 个硬数字；夯 ≥ 3 条
- [ ] 每个候选都搜过负面；拉完了有 `neg` 实锤
- [ ] 独立链接 ≥ max(10, 候选数×0.8)，≥ 6 个网站，≥ 3 类信源
- [ ] 时效性主题的关键数字都在 3 个月内
- [ ] 没有一条证据只来自 D 级线索
- [ ] 每个分数都能指到某条证据
