# 夯到拉排行榜

输入一个主题（可带尺寸，默认 3:4），输出：

- 一张榜单 PNG：五档「夯 / 顶级 / 人上人 / NPC / 拉完了」，每个候选带图标、加权分、一句锐评；页脚写评分维度、主要来源和截至日期
- `evidence.md`：评分维度和锚点、排名总表、每个候选的证据（带链接）、资料来源清单
- `data.json`：全部数据，改完可以重新出图

技能目录记为 `$SK`，就是本文件所在的目录（比如 `~/.claude/skills/z-hang-tierlist`、`<项目>/.agent/skills/z-hang-tierlist`）。下面命令里的 `$SK` 换成实际路径，或先 `export SK=该目录`。

依赖：Python 3 + Playwright（Chromium）+ Pillow，一次装好：

```bash
pip install -r "$SK/requirements.txt" && python3 -m playwright install chromium
```

字体默认思源宋体 VF（`~/Library/Fonts/SourceHanSerifSC-VF.ttf`），找不到时退回系统宋体，也可以用环境变量 `TIERLIST_FONT` 指定字体文件。

## 工作流（照做，不要跳步）

### 1. 定题

从用户的话里拿到这几样，没说的用默认值，不追问：

| 项 | 默认 | 说明 |
|---|---|---|
| 主题 | 必填 | 「国产大模型」「新茶饮品牌」「2026 旗舰手机」 |
| 范围 | 自己定 | 时间、地域、品类边界，写进 `scope`。比如「2026 年 11 月仍在售的、中国公司发布的旗舰模型，每家取最强的一款」 |
| 候选数 | 12-20 | 用户点名的候选必须全部收录 |
| 尺寸 | 3:4 | 用户说「小红书」用 3:4，「抖音/视频号/壁纸」用 9:16，「B站封面/PPT」用 16:9 |
| 风格 | `ink`（暗金） | 用户说浅色、白底、纸感时用 `paper`（宣纸） |

### 2. 建目录

```bash
python3 "$SK/scripts/tierlist.py" new "主题"
```

默认建在当前目录的 `夯到拉/<日期>-<主题>/`（`--out 目录` 指定位置，环境变量 `TIERLIST_OUT` 改根目录），里面有一份 `data.json` 骨架。后面的命令都在这个目录里运行。

### 3. 定维度和锚点

读 `references/rubrics.md`，按主题挑 3-5 个维度，权重加起来 100。每个维度写清 10 / 7 / 4 / 1 分各是什么样（`rubric`），锚点尽量绑定可查的数字（排名、评分、销量、价格），这样打分不靠感觉。

### 4. 广泛查资料（最花时间的一步，不能省）

读 `references/research.md`。硬性要求：

- **先查最新**：模型的知识有截止日期，先搜最近 1-3 个月的榜单和新闻，确认每个候选现在的最新版本、最新数字
- **三轮搜索**：① 全景（榜单、市场份额、年度盘点）定候选池；② 逐个候选查硬数据；③ 专门搜负面（翻车、投诉、召回、争议、差评）
- **信源分级**：一手和权威二手做依据，社区口碑做补充，营销号和 AI 生成的总结只当线索
- **数量**：每个候选至少 2 条证据、至少 1 个硬数字，进「夯」的至少 3 条；全榜独立链接 ≥ max(10, 候选数×0.8)，来自 ≥ 6 个网站、≥ 3 类信源
- **边查边记**：每条证据直接写进 `data.json` 对应候选的 `evidence`（text / source / url / date / type，负面加 `"neg": true`）

### 5. 打分、分档、写锐评

- **横向打分**：一次只看一个维度，把所有候选在这个维度上一起排一遍再给分，避免单个候选孤立打分时分数漂移
- 每个分数都要能指到 evidence 里的某条证据；拿不准的给保守分，并在 `summary` 里写明
- **分档交给脚本**：加权分 ≥ 9.0 夯，≥ 8.0 顶级，≥ 7.0 人上人，≥ 5.5 NPC，其余拉完了。某档空着就空着（图上显示「虚位以待」），不要硬凑
- 确有理由要改档（比如梗属性、口碑与数据严重背离），写 `tier` + `override_reason`，依据表里会公开写出来
- **锐评** `verdict`：≤ 12 字，一针见血，必须能在证据里找到依据。可以犀利，不人身攻击，不传谣；涉及公司和真人的负面只写可查证的事实
- 显示名太长（> 13 字宽）就写 `short`；图标按 `references/spec.md` 选 emoji、字标（`mono` + 品牌色 `color`）或本地图片

### 6. 校验，修到没有错误

```bash
python3 "$SK/scripts/tierlist.py" check data.json
```

终端会打出排名总表、分布、来源统计和提醒：

| 提醒 | 意思 | 怎么改 |
|---|---|---|
| `证据不足` / `没数字` / `没链接` | 某候选证据不够硬 | 回第 4 步补查，别靠编 |
| `夯要硬` | 进了夯却少于 3 条证据 | 补证据，或者老实降档 |
| `拉完了要实锤` | 进了拉完了却没有负面证据 | 补一条标 `neg` 的实锤，找不到就说明分数打低了 |
| `来源偏少` / `来源单一` / `信源类型少` | 资料面太窄 | 换信源类型再搜一轮 |
| `夯太多` / `扎堆` | 分数没拉开 | 回看 rubric，是不是没用满 0-10 分 |
| `压线` | 加权分离分档线不到 0.15 | 再核一遍这个候选的分数，确认后可以不改 |
| `锐评太长` / `名字太长` | 上图会挤或被截 | 缩短 verdict，写 short |
| 禁用词 | 出现了禁用词表（`forbid.txt`、`forbid.local.txt`）或 `data.json` 里 `forbid` 的词 | 改写 |

### 7. 出图

```bash
python3 "$SK/scripts/tierlist.py" build data.json                  # 默认 3:4，1200×1600
python3 "$SK/scripts/tierlist.py" build data.json --size 9:16      # 其他比例
python3 "$SK/scripts/tierlist.py" build data.json --size 3:4,16:9  # 一次出多张
python3 "$SK/scripts/tierlist.py" build data.json --size all       # 全部常见尺寸
python3 "$SK/scripts/tierlist.py" build data.json --theme paper    # 宣纸浅色
python3 "$SK/scripts/tierlist.py" build data.json --hd             # 2 倍图（3:4 为 2160×2880）
python3 "$SK/scripts/tierlist.py" build data.json --size 1242x1660 # 任意像素
```

| 比例 | 默认像素 | 场景 |
|---|---|---|
| 3:4 | 1200×1600 | 公众号配图、小红书（默认） |
| 4:5 | 1080×1350 | Instagram、朋友圈 |
| 1:1 | 1080×1080 | 方图、头像位 |
| 9:16 | 1080×1920 | 抖音、视频号、手机壁纸 |
| 2:3 | 1200×1800 | 长竖图 |
| 4:3 | 1600×1200 | 横版文章配图 |
| 16:9 | 1920×1080 | B站封面、PPT、视频画面 |

排版全自动：候选少时用方块卡片（图标大），多了换横条，再多换紧凑条；字号在能放下的前提下取最大。出图后终端会报排版模式和问题：

| 提醒 | 怎么改 |
|---|---|
| `溢出` | 候选太多：减到 30 个以内，或换 9:16 / 16:9 |
| `名字被截` | 写 `short` |
| `锐评被截` | 缩短 `verdict` |
| `页脚被截` | 缩短维度名，或写 `footer_sources` 自定义来源行 |

### 8. 看图（必须）

用读图工具打开每一张 PNG，检查：字压字、名字或锐评被截、某档挤成一团而别的档很空、emoji 显示成方框、图标颜色撞色难分辨、标题折行难看。有问题改 `data.json` 重新 build。

### 9. 交付

回复用户：

1. PNG 路径（每个尺寸一张）
2. 一段 5 行以内的结论：每档一句话说清谁在里面、凭什么
3. `evidence.md` 路径，提醒用户发布前可以按依据表抽查
4. 压线、改档、证据有分歧的候选单独点出来

## 硬规则

- 不编数字、不编来源。查不到就写查不到，分数给保守值
- 截至日期上图（页脚自动写），时效性强的主题（模型、手机、榜单）必须用最近 3 个月内的数据
- 拉完了必须有实锤；夯必须有 3 条以上证据
- 同一主题只出一套分数：多尺寸出图共用同一份 `data.json`，不要为了好看单独改某张图
- 图上不加个人签名、手记框；需要署名时写 `byline`，显示在页脚右侧
- 长期要避开的词写进 `$SK/forbid.local.txt`（不入库），单次任务的禁用词写进 `data.json` 的 `forbid`

## 文件

- `scripts/tierlist.py`：new / check / build 三个命令
- `assets/template.html`：版式模板（主题色、档位颜色、自适应排版都在这里）
- `references/research.md`：查资料的方法、信源分级、搜索词模板
- `references/rubrics.md`：常见主题的维度和打分锚点
- `references/spec.md`：`data.json` 字段说明
- `requirements.txt`：Python 依赖
- `forbid.txt`：禁用词表的说明（自己的词写进 `forbid.local.txt`，不入库）
- `examples/demo/`：虚构数据的完整示例（`data.json`、`evidence.md`、暗金和宣纸两张 PNG），照着改最快
