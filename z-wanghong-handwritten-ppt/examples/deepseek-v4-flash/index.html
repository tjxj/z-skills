82.5GB → 161.9GB，关键看体积—质量的断点

十三个档位从 82.5GB 到 161.9GB。名称很多，真正有用的是找到质量断点。

为什么 GGUF 没有明显变小

V4-Flash 做了量化感知训练 QAT

96% routed experts 已经是 MXFP4

剩余 4% 是 FP8 或 BF16

GGUF = 逐位重打包 → 专家权重一个 bit 都不动

文件没有明显缩小，因为百分之九十六的专家权重原本就是 MXFP4。GGUF 主要做格式重打包。

UD-Q8_K_XL：第一次看到真正的无损点

Q8 的困惑度和官方原版小数点后四位完全相同，KL 接近零，top-token 一致率百分之百。

体积继续下降，质量损失突然抬头

Q8：无损

Q4：KLD ≈ 0.01

IQ3：KLD 约为 Q4 的 25 倍

低于 4bit，开始真正改动专家权重

四位以下开始动专家权重，质量曲线从这里明显抬头。Q4 是这条曲线最值得记住的拐点。

13 个档位怎么选？

169GB+ → UD-Q8_K_XL：无损

162GB → UD-Q4_K_XL：首选

128GB → UD-IQ3_XXS：能用

<128GB → 直接用 API

一百六十九 GB 以上直接 Q8；一百六十二 GB 选 Q4；一百二十八 GB 再考虑 IQ3；更小内存建议用 API。
